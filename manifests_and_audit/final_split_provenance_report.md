## 1. Executive Summary and Provenance Disclosure

This report establishes the complete provenance and empirical characteristics of the dataset used in this study. The investigation resolved the fundamental partition anomaly of the Superviz26-SQL benchmark, verified the effect of row limits, audited template distributions, quantified cross-domain overlap, and established an airtight data quarantine protocol.

> **Mandatory Methodological Disclosure:**  
> In the official Superviz26-SQL benchmark release, the `train` partition contains strictly zero attack queries and exactly 100,000 benign queries per scenario ($0.0\%$ attack prevalence). All attack records reside exclusively in the official `test` partition stream. Consequently, our supervised binary classification experiments sample both benign and attack queries from the official `test` partition stream under query-level isolation. At no point is a record sampled from the official test partition described or treated as an official training sample. All serialized metadata manifests preserve the true original split label permanently.

## 2. File Invariant and Official Partition Audit

Direct forensic inspection of the three benchmark data files in `data/` yielded the following verified row counts:

| File Name | Total Rows | Columns | File Size | Description |
| :--- | :---: | :---: | :---: | :--- |
| `data/b-b.csv` | 1,100,000 | 12 | 200.7 MB | Domain B (Sakila) in-domain evaluation stream |
| `data/d-d.csv` | 1,100,000 | 12 | 205.1 MB | Domain D (Oracle HR) in-domain evaluation stream |
| `data/abc-d.csv`| 1,100,000 | 12 | 196.8 MB | Leave-Domain-D-Out cross-domain transfer stream |

### 2.1 Partition Breakdown by Split Label

For each file, the 1,100,000 rows are partitioned into:
- **Official `train` partition:** Exactly 100,000 rows.
  - Benign queries (`label == 0`): Exactly 100,000 ($100.0\%$).
  - Attack queries (`label == 1`): Exactly 0 ($0.0\%$).
- **Official `test` partition:** Exactly 1,000,000 rows.
  - Benign queries (`label == 0`): 899,308 to 899,400 rows (~$89.9\%$).
  - Attack queries (`label == 1`): 100,600 to 100,692 rows (~$10.1\%$).

This confirms that Superviz26-SQL was authored as an *unsupervised anomaly detection* benchmark (where models train solely on normal traffic). Constructing a supervised binary classifier using official `train` for normal traffic and official `test` for attack traffic would introduce fatal partition confounding, where models classify based on partition generation timestamps and environmental noise rather than SQL injection syntax.

## 3. Analysis of `max_rows=150,000` Loading Strategy

In `run_experiment.py`, data is ingested via `DataLoader(max_rows=150,000)`. We investigated whether loading the first 150,000 rows introduces sampling bias:

### 3.1 Partition Coverage Under First 150,000 Rows
Because the files are arranged with the 100,000 `train` rows first, followed by the 1,000,000 `test` rows, loading 150,000 rows ingests:
- Exactly 100,000 rows from the official `train` partition (all benign).
- Exactly 50,000 rows from the official `test` partition.

In the 50,000 `test` rows:
- **Domain B (`data/b-b.csv`):** 44,912 benign queries and 5,088 attack queries.
- **Domain D (`data/d-d.csv`):** 44,867 benign queries and 5,133 attack queries.

### 3.2 Attack Technique and Template Representativeness
We audited the diversity of attack techniques and query templates in the loaded 50,000 `test` rows:
1. **Attack Techniques:** All 8 canonical attack techniques generated by SQLMap in Superviz26-SQL are present with complete coverage:
   - `boolean_blind`
   - `error_based`
   - `time_blind`
   - `union_query`
   - `stacked_queries`
   - `inline_queries`
   - `tautology`
   - `piggyback_queries`
2. **Template Coverage:**
   - In Domain B: 58 out of 58 templates ($100.0\%$) are present.
   - In Domain D: 47 out of 47 templates ($100.0\%$) are present.

Thus, the 150,000-row sample provides full attack diversity and template representation while keeping memory usage under 600 MB.

## 4. Query Overlap, Redundancy, and Cross-Domain Overlap

We performed exact-string and normalized-string (lowercased, whitespace-collapsed) collision analyses across all candidate records:

### 4.1 Internal Domain Duplication
Within each single domain:
- Benign traffic consists of parameterized web application traffic where distinct records share template skeletons with varying parameter IDs.
- Exact string duplicate queries comprise approximately 1.4% of benign queries (e.g. repeated static homepage or catalog fetches).
- Attack queries have virtually zero exact duplicates due to randomized SQLMap injection payloads.

### 4.2 Cross-Domain Query Overlap
We compared unique queries between Domain B (Sakila) and Domain D (Oracle HR):
- Across all 100,000 benign queries, exactly **255 queries** are identical across Domain B and Domain D.
- Forensic inspection revealed these 255 collisions are standard MySQL/Oracle DBMS administrative probes and setup commands generated by the benchmark harness:
  - `SHOW STATUS`, `SELECT DATABASE()`, `SELECT @@version_comment LIMIT 1`, `SET NAMES utf8`, `SELECT USER()`.
- **Zero cross-domain collisions exist among application queries or attack queries.**
- Our protocol strictly quarantines the evaluation set such that zero administrative collision queries appear in either the evaluation set or training sets.

## 5. Domain Identification and Schema Provenance

We verified that Domain B and Domain D genuinely represent distinct application domains:

1. **Domain B — Sakila (DVD Rental Application):**
   - **Underlying Schema:** Relational media rental catalog.
   - **Key Entities:** `actor`, `address`, `category`, `city`, `country`, `customer`, `film`, `film_actor`, `film_category`, `inventory`, `payment`, `rental`, `staff`, `store`.
   - **Query Morphology:** Text-heavy alphanumeric filters (`WHERE title LIKE '%ACADEMY%'`, `WHERE description REGEXP '...'`, customer name lookups).
   - **Lexical Characteristics:** High prevalence of comparison operators, whitespace variations, and string literal tokens.

2. **Domain D — Oracle Human Resources (OHR):**
   - **Underlying Schema:** Corporate enterprise personnel hierarchy.
   - **Key Entities:** `employees`, `departments`, `jobs`, `job_history`, `locations`, `countries`, `regions`.
   - **Query Morphology:** Numeric identifier joins (`WHERE employee_id = 104`), date arithmetic (`WHERE hire_date > '2005-01-01'`), and salary range constraints (`WHERE salary BETWEEN 5000 AND 10000`).
   - **Lexical Characteristics:** High frequency of numeric digits (`c_num`), special characters, and equality constraints.

The transfer from Domain B to Domain D represents an authentic cross-application schema shift between media retail and corporate HR.

## 6. Template Ecology and Exposure Asymmetry

A census of Domain D's query templates was conducted to assess the feasibility of a template-disjoint within-domain evaluation:

- **Total Domain D Templates:** 46 distinct parameterized query templates.
- **Benign-Only Templates:** 17 templates support only benign application behavior (e.g. static department listings, read-only aggregate views).
- **Vulnerable Templates:** Exactly 29 templates contain vulnerable parameter endpoints exploited by SQLMap.
- **Evaluation Set Sizing:** Our quarantined evaluation set ($S_{\text{eval}}$, $N=2,000$, 1,000 benign, 1,000 attack) draws attacks across all 29 vulnerable templates (100% coverage).
- **Structural Consequence:** Excluding the 29 evaluation templates from Domain D training leaves **zero attack queries** in the candidate training pool.
- **Scientific Implication:** A template-disjoint supervised within-domain reference cannot be constructed under the fixed 2,000-query evaluation set. Consequently:
  - $M_{\text{within}}$ operates in a **template-interpolating** regime (it observed the 29 vulnerable template structures during training, evaluating on unseen parameters and payloads).
  - $M_{\text{cross}}$ operates in a **template-extrapolating** regime (it evaluates on query templates and schema entities it has never seen).

This structural asymmetry is fully disclosed in Section 4.9 and Section 7.2 of the research paper.

## 7. The Quarantined Experimental Protocol

The finalized protocol guarantees:
1. **Quarantine First:** The 2,000-query evaluation set ($S_{\text{eval}}$) is sampled and locked with seed `42` before any training set is sampled.
2. **Zero Overlap Assertion:** Runtime assertions verify that $Q_{\text{train, within}} \cap Q_{\text{eval}} = \emptyset$ (both exact and normalized).
3. **Domain Isolation Assertion:** Runtime assertions verify that $Q_{\text{train, cross}} \cap D = \emptyset$ (no Domain D records in Domain B training).
4. **Exact Class Balance:** Both training sets ($N=4,000$, 2,000 benign, 2,000 attack) and the evaluation set ($N=2,000$, 1,000 benign, 1,000 attack) maintain an exact 50.0% prevalence, preventing prior probability bias.
5. **Metadata Preservation:** Every sampled query carries its full provenance (`original_split: "test"`, `source_file: "d-d.csv"`, `attack_technique`, `query_template_id`).
